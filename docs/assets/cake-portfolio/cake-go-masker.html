02/06
Developer Experience

使用者只要標 tag，
遮罩規則就跟著資料模型走。

API 設計重點是少記憶負擔：欄位旁邊直接寫 `mask:"email"`、`mask:"mobile"`，呼叫 Struct 或 Format 取得一致結果。

type User struct {
Name string `mask:"name"`
Email string `mask:"email"`
Password string `mask:"password"`
Mobile string `mask:"mobile"`
}
// → J**n D**e joh****@gmail.com ************** 0987***321
Struct()→ Marshal()→ Format()→ Sensitive[T]
作品集亮點：不只做「字串取代」，而是設計一套讓呼叫端自然寫對、也容易測試的 API surface。

03/06
Sensitive[T]

預設輸出是遮罩，
要看原文必須明確 Reveal。

Sensitive[T] 把敏感值包成型別：fmt、JSON、slog 都走遮罩輸出，只有呼叫 Reveal() 才能取得原始值。

fmt.Stringer fmt.Println(phone) 只會看到遮罩後電話，不把原文丟到 console。
json.Marshaler API response 或 debug dump 也遵守同一套遮罩語意。
slog.LogValuer 結構化 log 裡的敏感欄位同樣自動保護。
driver.Valuer DB 寫入保留原值，應用層輸出維持遮罩。
phone := masker.NewPhone("0987654321")
fmt.Println(phone) // 0987***321
fmt.Println(phone.Reveal()) // 0987654321
型別安全 · explicit reveal only Sensitive[T]

04/06
Built-in Rules

常見個資欄位，
內建規則一次補齊。

從 password、email、mobile 到 credit、URL password、地址、敏感詞字典，涵蓋後端服務最常遇到的輸出風險。

email / mobile保留識別所需片段，遮掉中段資訊：`ggw****@gmail.com`、`0987***321`。
id / credit依位數規則遮罩證號與卡號，避免 log 直接留下完整敏感資料。
struct / mapstruct遞迴處理 nested struct、pointer、slice、map value，key 保持不變。
abuseTrie-based word masking，可從檔案或 reader 載入自訂敏感詞。
first-N / last-N用 tag 表達動態遮罩規則，不需要為每個欄位新增一個 masker。

Reliability

遮罩是安全邊界，
所以測試不能只看 happy path。

專案補上 v2 parity、race、format allocation、SQL scan/value、redact mode 等測試，確保 library 行為穩定。

AC-07
Format 與 Struct 行為一致log-friendly output 不配置新 struct，但遮罩結果與 Struct() byte-identical。
AC-09
降低配置成本針對 Format() 做 allocation 測試，讓 debug/log path 更輕量。
AC-14
Abuse 字典遮罩敏感詞載入、命中、不同 mask char 與 struct tag 整合都有對應案例。
